# ТЗ: прототип городского ИИ-помощника по прогулкам (Астана)

Oct 22, 2026 · @Аверьянов Максим

## 1. Назначение и рамки

Прототип — Android-приложение для Астаны: карта 2ГИС с поиском и навигатором, ИИ-рекомендации по свободному запросу, лента «Для вас» и автоматические уведомления во время прогулки. Всё собирается на сервисах с самостоятельным подключением, без ожидания ответов от поставщиков.

Контекст: хакатон Build with AI, задача НИЦ Smart City «ИИ-помощник по прогулкам в городе Астана». Прототип обязан выполнить требования задачи: 1–3 рекомендации с причиной, временем на посещение и действием; пометка источника (данные о месте или идея модели); честность о режиме работы; минимум хранимых координат; автоматизированный сбор данных.

**Роли нейросетей**

- **Jev** (TypeSafe AI, класс System One) — определяет и применяет фильтры по запросу пользователя. Текст не генерирует.
- **Claude Haiku 5.5** — ответ в простом режиме, обновление портрета, тексты карточек и уведомлений.
- **Claude Sonnet 5.5** — режим плана (маршруты из нескольких точек). Модель каждой роли Claude задаётся конфигом.

**Входит в прототип**

- Главный экран: карта, строка запроса, чипы фильтров Jev, 1–3 рекомендации.
- Режим плана: маршрут из нескольких точек с учётом погоды и времени.
- Полноценная карта: поиск адресов и организаций, карточка места, маршруты для всех видов транспорта, пошаговая навигация в приложении.
- Портрет пользователя, дополняемый моделью после каждого поиска.
- Раздел «Для вас»: колода карточек, подобранных в фоне, управление свайпами.
- Автоматическое определение прогулки и контекстные уведомления без ручного включения.
- Учёт типа транспорта во всех расчётах времени и радиуса.

**Не входит**

- iOS и веб-версия.
- Аккаунты и синхронизация: портрет и история живут на устройстве.
- Офлайн-карты.
- Публикация в Google Play: для фоновой геолокации нужна отдельная декларация, это за рамками прототипа.

## 3. Jev: контракт интеграции

Jev вызывается один раз на каждый запрос пользователя и только с сервера: на вход — состояние (запрос и контекст), на выход — типизированные ответы с вероятностями. Это единственный источник фильтров: код поиска и Claude получают уже готовый объект `JevFilters`.

**API** ([справочник TypeSafe](https://docs.typesafe.ai/api/system-one.md))

- `POST https://api.typesafe.ai/v1/systemone`, заголовок `Authorization: Bearer <KEY>`. Список моделей — `GET /v1/models`.
- Тело запроса: `model`, `state` (строка, объект или массив), `questions` (именованные вопросы). В прототипе версия фиксируется: `jev-1.13.0`, а не `jev-latest`.
- Типы вопросов: `noul` — да/нет, ответ — вероятность «да»; `choice` — 1–255 вариантов в `criteria`, ответ — `choice`, `confidence`, `probabilities`; `score` — 1–10 упорядоченных уровней.
- Ответ: `answers` с теми же именами, что у вопросов, и `usage`. Ошибка валидации — HTTP 422 со списком `detail`.
- Лимиты Jev 1.13: 64 тыс. токенов всего, из них 32 тыс. на состояние плюс самый длинный вопрос ([Opper](https://docs.opper.ai/build/gateway/evaluations)). Потоковой выдачи нет.
- Вопросы оцениваются независимо друг от друга ([Maxim](https://www.getmaxim.ai/articles/what-is-jev-system-one-model/)). Зависимые решения собирает код.

**Доступ.** Jev в раннем доступе с 15 сентября 2026 года ([DigitalOcean](https://www.digitalocean.com/resources/articles/what-is-jev)). Если прямого ключа нет, Jev доступен через Vercel AI Gateway, OpenRouter (бета) и Cloudflare AI Gateway без листа ожидания ([OpenTweet](https://opentweet.io/jev/api-access)). Opper принимает тот же формат запроса по своему адресу, но требует платного плана. Поэтому `JevClient` берёт базовый адрес из `JEV_BASE_URL`.

**Состояние (`state`)** — объект без координат, Jev они не нужны:

```json
{
  "query": "нет зонта, через 30 минут дождь, хочу в кофейню",
  "local_time": "2026-10-22T17:40",
  "weekday": "thu",
  "is_holiday": false,
  "walk_active": true,
  "transport_detected": "walking",
  "weather": {"temp_c": 6, "precip_starts_in_min": 30, "wind_ms": 7},
  "profile_hint": "часто кофейни, пешком, без детей"
}
```

**Набор вопросов** (один запрос к Jev на все вопросы сразу)

| Имя | Тип | Варианты | Применение |
| --- | --- | --- | --- |
| `intent` | choice | `find_place`, `plan_route`, `navigate_to`, `place_info`, `other` | Выбор конвейера: простой режим, план, поиск по карте |
| `category_primary` | choice | \~50 категорий из раздела 4 + `none` | Запрос и рубрики 2ГИС |
| `category_secondary` | choice | те же + `none` | Вторая потребность, режим плана |
| `purchase_item` | choice | `umbrella`, `raincoat`, `powerbank`, `pharmacy`, `water_snack`, `flowers`, `gift`, `sim_topup`, `cash_atm`, `none` | Промежуточная точка «купить» |
| `transport` | choice | `walking`, `bicycle`, `scooter`, `driving`, `taxi`, `public_transport`, `unspecified` | Тип маршрута и матрицы времени |
| `max_travel` | choice | `5`, `10`, `20`, `40`, `unspecified` (мин) | Радиус поиска и отсев по времени в пути |
| `time_budget` | choice | `15`, `30`, `60`, `120`, `more`, `unspecified` (мин) | Отбор по времени на посещение |
| `open_requirement` | choice | `now`, `at_arrival`, `late`, `24h`, `unspecified` | Параметр `work_time` |
| `company` | choice | `solo`, `pair`, `kids`, `group_small`, `group_large`, `unspecified` | Категории и атрибуты |
| `kids_age` | choice | `under_3`, `3_7`, `8_12`, `teen`, `none` | Детские категории |
| `price` | choice | `free`, `budget`, `mid`, `premium`, `unspecified` | Средний чек |
| `ambience` | choice | `quiet`, `lively`, `romantic`, `family`, `work`, `any` | Мягкое ранжирование |
| `min_rating` | choice | `any`, `4.0`, `4.5` | Отсев по рейтингу |
| `novelty` | choice | `new_places`, `not_visited`, `any` | Новые места и история на устройстве |
| `indoor` | noul | — | Только крытые категории |
| `wifi`, `sockets`, `card_payment`, `parking`, `terrace`, `accessible`, `pets`, `halal`, `vegetarian`, `toilet` | noul, каждый отдельным вопросом | — | Атрибуты 2ГИС или мягкий бонус |
| `exclude_chains` | noul | — | Исключение сетевых заведений |

**Пороги применения**

- `choice`: вариант принимается при `confidence` ≥ 0,55, иначе считается `unspecified`.
- `noul`: ≥ 0,80 — жёсткий фильтр; 0,55–0,80 — мягкий бонус к рангу; ниже 0,55 — не применяется.
- Пороги стартовые и калибруются на размеченном наборе из 60 запросов (раздел 15). В одном исследовании вероятности Jev оказались плохо откалиброваны ([arXiv](https://arxiv.org/pdf/2609.36154)), поэтому без проверки на своих данных им не доверяем.

**Что делает код вокруг Jev.** Jev не возвращает текст и произвольные числа.

- Числа из запроса (минуты, тенге, число людей) извлекает регулярное выражение. Точное значение заменяет корзину Jev того же смысла.
- Строку `q` для 2ГИС собирает код из таблицы соответствий (раздел 4).
- При `intent` = `navigate_to` или `place_info`, а также при `confidence` категории ниже 0,55 в `q` уходит исходный текст. Полнотекстовый поиск 2ГИС понимает названия и адреса.

**Ошибки**

- Таймаут 1,5 с. Заявленная задержка Jev — 70–500 мс ([DataCamp](https://www.datacamp.com/ja/blog/system-one-models-jev)), это данные производителя.
- 429 и 5xx — один повтор с учётом `Retry-After`. 422 — ошибка в схеме вопросов: логировать, не повторять.
- Jev недоступен — поиск идёт по исходному тексту без фильтров, в интерфейсе чип «Фильтры не определены».

**Результат — объект `JevFilters`**, собранный кодом из ответов:

```json
{
  "intent": "plan_route",
  "category_primary": {"id": "coffee", "p": 0.86},
  "category_secondary": null,
  "purchase_item": {"id": "umbrella", "p": 0.91},
  "transport": "walking",
  "max_travel_min": 10,
  "time_budget_min": null,
  "open": "at_arrival",
  "hard": ["indoor"],
  "soft": ["wifi"],
  "event_offset_min": 30
}
```

## 4. Фильтры и соответствие 2ГИС

Каждый фильтр Jev становится либо параметром запроса к 2ГИС, либо отсевом и ранжированием в коде. Если 2ГИС не хранит признак, фильтр работает как мягкий бонус, а в ответе помечается «не подтверждено».

**Параметры Places API** (`GET https://catalog.api.2gis.com/3.0/items`)

- `q` — текст запроса. Places API ищет и по товарам и услугам, например «кафе с итальянской кухней» ([2ГИС](https://docs.2gis.com/en/api/search/places/overview)).
- Геоограничение по точке и радиусу; сортировка по расстоянию или рейтингу ([2ГИС](https://docs.2gis.com/en/api/search/places/examples/results)).
- `work_time` — `now` или день со временем, например `today,09:00`; `opened_after_date` — новые места ([2ГИС](https://docs.2gis.com/en/api/search/places/examples/filtering)).
- Фильтры наличия рейтинга, отзывов, фото и дополнительные атрибуты (Wi-Fi, оплата картой). Список атрибутов динамический и приходит в `result.filters.attributes`.
- Демо-ключ: не больше 10 объектов на страницу и 5 страниц ([2ГИС](https://docs.2gis.com/api/search/overview)).
- Точные имена полей ответа (режим работы, рейтинг, атрибуты, число филиалов) разработчик сверяет со справочником API в первый день.

**Каталог фильтров**

| Группа | Фильтр | Источник значения | Применение |
| --- | --- | --- | --- |
| Транспорт | Вид транспорта | Jev `transport`; иначе детектор активности; иначе профиль | Параметр `transport` матрицы и маршрутов |
| Транспорт | Время в пути | Jev `max_travel` или число из запроса | Радиус = скорость × время; точный отсев по матрице |
| Время | Открыто сейчас, к прибытию, допоздна, круглосуточно | Jev `open_requirement` | `work_time`; «к прибытию» = сейчас + время в пути |
| Время | Время на посещение | Jev `time_budget` или число из запроса | `visit_min` категории ≤ бюджет − дорога |
| Погода | Крытое место | Jev `indoor` или триггер погоды | Флаг `indoor` категории |
| Компания | Дети и их возраст | Jev `company`, `kids_age` | Флаг `kids` категории, атрибут «детская комната» |
| Компания | Группа | Jev `company` | Мягкий бонус категориям для групп |
| Удобства | Wi-Fi, оплата картой, веранда, парковка | Jev `noul` | Атрибуты 2ГИС |
| Удобства | Розетки, туалет | Jev `noul` | Мягкий бонус; без атрибута — «не подтверждено» |
| Удобства | Доступная среда | Jev `accessible` | Атрибут доступности ([такой фильтр есть в 2ГИС](https://help.2gis.com/question/how-to-filter-companies-in-search-results)) |
| Еда | Халяль, вегетарианское, кухня | Jev `noul` и категория | Атрибуты или слово в `q` («халяль кафе») |
| Цена | Бесплатно … премиум | Jev `price` или сумма в тенге из запроса | Средний чек (есть в 2ГИС для заведений питания) |
| Качество | Минимальный рейтинг | Jev `min_rating` | Отсев по рейтингу с поправкой на число отзывов (раздел 5) |
| Новизна | Новые или не посещённые | Jev `novelty` | `opened_after_date`; список посещённых на устройстве |
| Атмосфера | Тихо, оживлённо, для работы | Jev `ambience` | Мягкий бонус по категории и портрету; в ответе «оценка модели» |
| Исключения | Без сетевых | Jev `exclude_chains` | По числу филиалов организации |

Скорости для радиуса поиска (конфиг, км/ч): пешком 4,5; велосипед 15; самокат 12; авто и такси 25; общественный транспорт 15. Радиус лишь сужает поиск; окончательно время считает матрица 2ГИС.

## 5. Простой режим: поиск и ответ

Простой режим отвечает 1–3 рекомендациями. Факты о месте (время в пути, режим работы, рейтинг) подставляет код. Claude Haiku 5.5 выбирает места только из списка кандидатов и пишет причину, время на посещение и действие.

**Конвейер**

1. Клиент отправляет `POST /v1/search` (SSE): запрос, координаты, округлённые до 3 знаков (около 110 м), локальное время, транспорт от детектора, флаг прогулки, сводку портрета.
2. Сервер берёт погоду из кэша (ячейка geohash 5, 10 минут) и вызывает Jev. После ответа Jev уходит событие `filters`, клиент показывает чипы.
3. Запросы к Places API: до 2 (основная и дополнительная категория), до 20 кандидатов. Радиус — по разделу 4, `work_time` — по требованию к режиму работы, атрибуты — из жёстких фильтров.
4. Один запрос к Distance Matrix API: источник — пользователь, цели — кандидаты. Параметр `transport` принимает `walking`, `bicycle`, `scooter`, `driving`, `taxi`, `public_transport` и другие ([2ГИС](https://docs.2gis.com/en/api/navigation/distance-matrix/reference/get_dist_matrix)).
5. Отсев кодом: время в пути больше лимита; закрыто к моменту прибытия. Режим работы разбирается в три состояния: «открыто», «закрыто», «нет данных». Третье не отсеивается, а помечается.
6. Ранжирование по формуле ниже, 8 лучших — событие `candidates`, маркеры на карте.
7. Claude Haiku 5.5 выбирает 1–3 места — событие `answer`, карточки в шторке. Затем `done`.

**Ранжирование**

```latex
s = 0.35\,R + 0.25\,e^{-t/\tau} + 0.20\,Q + 0.10\,P + 0.10\,O
```

- R — соответствие запросу: вероятность категории от Jev и доля совпавших мягких фильтров, 0–1.
- t — время в пути в минутах; τ — половина лимита времени в пути.
- Q — рейтинг с поправкой на число отзывов (формула ниже). Она не даёт месту с «5,0 при двух отзывах» обойти место с 4,7 при тысяче.
- P — близость к портрету, 0–1 (раздел 8).
- O — уверенность в режиме работы: открыто 1, нет данных 0,5.

```latex
\bar r = \frac{n\,r + C\,m}{n + C}, \qquad Q = \frac{\bar r - 1}{4}, \qquad m = 4.2,\; C = 10
```

Здесь n — число отзывов, r — средняя оценка по шкале 1–5. Веса и константы стартовые, их подбирают на тестовых сценариях.

**Вызов Claude**

- Модель `claude-haiku-5-5`, `output_config.effort = "low"`. Ответ строго по JSON-схеме через `output_config.format` ([Claude](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)).
- В промпт: запрос, `JevFilters`, контекст (время, погода, транспорт), сводка портрета, 8 кандидатов с фактами. Координаты не передаются.
- Правила системного промпта: только кандидаты из списка; не писать «открыто» при состоянии «нет данных»; язык ответа равен языку запроса (русский, казахский, английский); одна фраза «почему»; конкретное действие.
- `poi_id` — перечисление id кандидатов, поэтому место вне списка в ответ не попадёт. Поддержку `enum` в подмножестве JSON Schema проверить в первый день (уверенность около 85%). Длины строк и число элементов дополнительно проверяет код.

```json
{
  "type": "object",
  "additionalProperties": false,
  "required": ["items", "idea"],
  "properties": {
    "items": {
      "type": "array",
      "items": {
        "type": "object",
        "additionalProperties": false,
        "required": ["poi_id", "why", "visit_min", "action"],
        "properties": {
          "poi_id": {"type": "string", "enum": ["<id кандидата 1>", "<id кандидата 8>"]},
          "why": {"type": "string"},
          "visit_min": {"type": "integer"},
          "action": {"type": "string"}
        }
      }
    },
    "idea": {"type": ["string", "null"]}
  }
}
```

Поле `idea` — необязательная идея без привязки к месту. В интерфейсе она идёт с меткой «Идея модели», рекомендации — с меткой «Данные 2ГИС».

**Крайние случаи**

- Нет кандидатов → радиус × 1,5 один раз → снять мягкие фильтры → честный ответ «ничего не найдено» со списком ослабленных условий.
- Jev недоступен → поиск по исходному тексту (раздел 3).
- Claude не ответил за 6 с → топ-3 кандидата без текста «почему», с пометкой.

## 6. Режим плана: маршрут из нескольких точек

Режим плана строит маршрут «промежуточные точки → цель» с ограничениями по времени. Пример: «зонта нет, через 30 минут дождь, хочу в кофейню», а рядом кофеен нет. Оптимум считает код полным перебором; Claude Sonnet 5.5 переформулирует поиск, когда кандидатов нет, и объясняет итог.

**Когда включается:** `intent` = `plan_route`, или `purchase_item` ≠ `none`, или `category_secondary` ≠ `none`.

**Алгоритм**

1. Роли: промежуточные точки — `purchase_item` и `category_secondary`, цель — `category_primary`.
2. Ограничение: если осадки начнутся через t\_rain (раздел 10), точка с зонтом или крытая цель должна быть достигнута до t\_rain − 3 мин.
3. Прямой вариант: если лучшая цель достижима до t\_rain, маршрут прямой, без промежуточной точки.
4. Кандидаты: 6 промежуточных точек (W) и 6 целей (D), открытых к моменту прибытия.
5. Один запрос к матрице: точки = пользователь + W + D; `sources` = пользователь и W; `targets` = W и D.
6. Перебор 36 пар (w, d) по формуле ниже. Если допустимых пар нет, сначала минимизируется время под дождём, потом общее время.
7. Три и больше промежуточных точек: до 4 точек — перебор порядков в коде (24 варианта), больше — TSP API 2ГИС, который решает задачу обхода точек ([2ГИС](https://dev.2gis.ru/en/api/routing)).
8. Геометрия маршрута — Routing API с промежуточными точками для выбранного транспорта.
9. Ответ: этапы, общее время, время под дождём, объяснение.

```latex
(w^*, d^*) = \arg\min_{(w,d)\,:\; t_{uw} \le t_{rain} - 3} \left( t_{uw} + 5 + t_{wd} \right)
```

Здесь t\_uw — время от пользователя до точки w, t\_wd — от w до цели d, 5 — минуты на покупку (конфиг).

**Инструменты Claude Sonnet 5.5**

| Инструмент | Что делает | Вход | Выход |
| --- | --- | --- | --- |
| `search_places` | Поиск в 2ГИС с фильтрами | `q`, `category_id`, фильтры, радиус | Кандидаты с фактами |
| `travel_matrix` | Матрица времени в пути | id точек, транспорт | Минуты между точками |
| `plan_route` | Оптимизатор из шагов 5–7 | Пользователь, W, D, ограничения | Лучший план и 2 альтернативы |
| `weather_nowcast` | Осадки на час вперёд | Ячейка geohash 5 | t\_rain, интенсивность |

**Правила вызова**

- Модель `claude-sonnet-5-5` (конфиг `PLANNER_MODEL`), effort `medium`, не больше 6 вызовов инструментов на запрос.
- Все инструменты с `strict: true` и `tool_choice: auto`. Принудительный вызов инструмента Sonnet 5.5 не поддерживает ([Claude](https://platform.claude.com/docs/en/models/sonnet-5-5/migration-guide)).
- Если кандидаты есть в обоих наборах, план собирает код, а Sonnet пишет только объяснение. Цикл инструментов запускается, когда один из наборов пуст.
- Запасные запросы для зонта: «супермаркет», затем «торговый центр»: крытая цель сама решает проблему дождя.
- 2ГИС находит магазины по товарам, но не гарантирует наличие. Ответ всегда помечает «наличие зонтов не подтверждено».

**Формат плана**

```json
{
  "legs": [
    {"to": "<id магазина>", "purpose": "купить зонт", "transport": "walking", "eta_min": 6},
    {"to": "<id кофейни>", "purpose": "кофейня", "transport": "walking", "eta_min": 9}
  ],
  "total_min": 20,
  "rain_exposure_min": 0,
  "notes": ["наличие зонтов не подтверждено"],
  "explanation": "<текст модели>"
}
```

## 7. Карта и навигатор

Карта — 2ГИС MapGL JS внутри WebView; ключ создаётся сразу в Менеджере Платформы, без заявок. Навигатор — свой, на манёврах Routing API и синтезе речи Android; запасной путь — открыть маршрут в приложении 2ГИС.

**Ключ и лимиты.** Бесплатный демо-ключ создаётся один раз, действует месяц и даёт 1000 запросов на каждый сервис ([2ГИС](https://docs.2gis.com/platform-manager/subscription/keys)). Он подходит для Map Tiles API, на котором работает MapGL ([2ГИС](https://docs.2gis.com/mapgl/start/first-steps)). Ключи с нужными месячными лимитами покупаются там же самостоятельно, там же ключ ограничивается по приложению ([2ГИС](https://docs.2gis.com/ru/platform-manager/keys)).

**Почему не нативный SDK.** Android SDK 2ГИС в версии Full включает навигатор ([2ГИС](https://docs.2gis.com/ru/android/native/maps/overview)), но демо-ключей для мобильного SDK нет ([2ГИС](https://docs.2gis.com/react-native/sdk/start)), нужна платная подписка. Карта подключается через интерфейс `MapProvider`, поэтому переход на SDK позже — замена одной реализации.

**Карта в WebView**

- HTML-страница в `assets` загружает `https://mapgl.2gis.com/api/js/v1` и создаёт карту с ключом.
- Мост Kotlin ↔ JS через `WebMessagePort`. Команды из Kotlin: `setCenter`, `setUserLocation`, `setMarkers`, `drawRoute`, `fitBounds`, `clear`. События в Kotlin: `markerClick`, `mapLongPress`, `cameraIdle`.
- Маркеры: номера 1–3 для рекомендаций, иконки категорий для остальных кандидатов.
- Расходуют ли загрузки карты лимит демо-ключа, не проверено. В первый день сверить со статистикой Менеджера Платформы.

**Поиск по карте**

- Подсказки при вводе — Suggest API, результаты — Places API, адреса — Geocoder API.
- Одна строка ввода для всего: выбор подсказки открывает карточку места, отправка текста запускает ИИ-поиск (раздел 5).

**Карточка места:** название, рубрика, адрес, режим работы и состояние сейчас, рейтинг и число отзывов, контакты, атрибуты. Places API отдаёт по отзывам только агрегат ([2ГИС](https://docs.2gis.com/api/search/overview)). Кнопки: «Маршрут», «Позвонить», «Открыть в 2ГИС».

**Маршруты.** Routing API для пешехода, велосипеда, самоката, авто и такси; общественный транспорт — Public Transport API ([2ГИС](https://dev.2gis.ru/en/api/routing)). Переключатель транспорта в шторке маршрута; по умолчанию — транспорт пользователя.

**Пошаговая навигация**

1. Ответ маршрутизатора 2ГИС содержит длину, время и список манёвров `maneuvers` ([2ГИС](https://docs.2gis.com/en/api/navigation/directions/overview)). Точный формат манёвров в Routing API сверить со справочником в первый день.
2. Сервис переднего плана с геолокацией, обновление раз в секунду, позиция привязывается к линии маршрута.
3. Карточка следующего манёвра и расстояние до него. Голос через `TextToSpeech` (ru-RU): на авто за 200 и 50 м, пешком за 50 и 15 м.
4. Сход с маршрута: дальше 30 м от линии пешком (50 м на авто) дольше 8 с → перестроение, не чаще раза в 20 с.
5. Прибытие: радиус 25 м → экран «Вы на месте» и карточка места.
6. Запасной путь: ссылка `dgis://2gis.ru/routeSearch/rsType/<тип>/from/<lon>,<lat>/to/<lon>,<lat>` открывает маршрут в приложении 2ГИС ([2ГИС](https://help.2gis.com/question/developers-launching-2gis-navigation-using-deeplink)). Подтверждено значение `car`; значения для пешехода и транспорта проверить.

## 8. Портрет пользователя

Портрет хранится только на устройстве и пополняется после каждого поиска. Фоновая задача отправляет итог поиска на сервер, Claude Haiku 5.5 возвращает операции над портретом, устройство применяет их по фиксированным правилам. Сервер ничего не хранит.

**Состав портрета** — только разрешённые ключи, другие модель записать не может:

| Ключ | Что хранит | Пример |
| --- | --- | --- |
| `category.<id>` | Интерес к категории: счётчики Beta(α, β) | `category.coffee`: α = 9, β = 2 |
| `cuisine` | Любимые и нелюбимые кухни | грузинская +, фастфуд − |
| `ambience` | Атмосфера | тихо |
| `price_level` | Ценовой уровень | средний |
| `time_pattern` | Привычное время по группам категорий | кофейни — будни утром |
| `transport_default` | Транспорт по умолчанию и по контексту | пешком; вечером такси |
| `company` | С кем обычно ходит | один; по выходным с детьми |
| `walk_tolerance` | Комфортная длительность прогулки | до 60 мин |
| `dislikes` | Явные антипатии | шумные места |
| `explicit` | Прямые заявления, до 120 символов | «люблю виды на город» |

У каждого факта: значение, уверенность c от 0 до 1, число подтверждений, дата последнего подтверждения, источник (явный или выведенный).

**Конвейер обновления**

1. Поиск завершён: выбрано место, начат или завершён маршрут, поиск закрыт без выбора или запрос переформулирован. Приложение формирует событие: запрос, главные фильтры Jev, показанные места (id, категория, время в пути), действие пользователя, время, погоду.
2. WorkManager при наличии сети отправляет `POST /v1/profile/update`: событие и текущую сводку портрета.
3. Сервер вызывает `claude-haiku-5-5` (effort `low`) с JSON-схемой ответа: список операций `add`, `reinforce`, `weaken`, `remove`; `key` — перечисление разрешённых ключей; `evidence` — основание до 80 символов.
4. Устройство применяет операции по правилам ниже и пересобирает сводку.

**Правила слияния**

```latex
c_{\text{add}} \in \{0.8_{\text{explicit}},\ 0.3_{\text{implicit}}\}, \quad c_{\text{reinforce}} = c + 0.2\,(1 - c), \quad c_{\text{weaken}} = 0.8\,c, \quad c_{\text{day}} = c \cdot 2^{-\Delta d / 30}
```

- `remove` удаляет факт; факт с c < 0,1 удаляется сам. Не больше 200 фактов.
- Свайпы и посещения меняют счётчики категорий напрямую, без модели: «хочу» — α + 1, дойденный маршрут — α + 2, «не то» — β + 1. Стартовое значение α = β = 1.
- Близость к портрету для ранжирования (величина P в разделе 5): α / (α + β) категории места плюс 0,1 за каждый совпавший факт, не больше 1.

**Ограничения**

- Модели запрещено выводить здоровье, религию, национальность, политические взгляды, финансовое положение. Пищевые предпочтения (халяль, вегетарианство) сохраняются только как прямое заявление пользователя.
- Сводку для промптов собирает код из 15 самых уверенных фактов, до 300 токенов.
- Экран «Мой портрет»: просмотр, правка и удаление факта, удаление всего портрета.

## 9. Раздел «Для вас»

Колода из 20 карточек собирается в фоне заранее, поэтому вкладка открывается мгновенно. Подбор идёт по портрету, месту, времени, дате и погоде; пользователю не нужно знать, что искать.

**Когда обновляется:** WorkManager раз в 4 часа (есть сеть, батарея не разряжена), при открытии приложения, если колоде больше 2 часов, и в начале прогулки. На демо-ключе 2ГИС — не чаще 3 раз в сутки.

**Подбор**

1. Район: текущая ячейка geohash 6 (около 1,2 × 0,6 км); с платным ключом 2ГИС — ещё до 3 частых районов. Частые районы считает устройство по истории посещений; история не покидает телефон.
2. Категории: 3 выбираются сэмплированием Томпсона из счётчиков портрета, 1 — случайно, чтобы пробовать новое.
3. Запрос `POST /v1/deck`: сервер делает по одному запросу Places API на категорию (до 10 мест), считает время в пути одним запросом к матрице и добавляет погоду на 3 часа, время восхода и заката, признак выходного или праздника.
4. Ранжирование на устройстве по формуле ниже, затем отбор 20 карточек с учётом разнообразия.
5. Тексты «почему»: один вызов Claude Haiku 5.5 на всю колоду, до 100 символов на карточку. Личную часть («вы часто ходите в кофейни утром») добавляет шаблон на устройстве.

**Ранжирование карточек**

```latex
s = 0.30\,\theta + 0.20\,K + 0.20\,e^{-t/10} + 0.15\,Q + 0.15\,N, \qquad \theta \sim \mathrm{Beta}(\alpha, \beta)
```

- θ — одна выборка из счётчиков категории на каждое обновление: любимые категории побеждают чаще, но не всегда.
- K — соответствие контексту (таблица ниже).
- t — время в пути на транспорте пользователя, мин.
- Q — рейтинг с поправкой на число отзывов (раздел 5).
- N — новизна: 1 — не посещалось, 0,3 — посещалось за 30 дней.

| Условие | K для крытых мест | K для открытых мест |
| --- | --- | --- |
| Осадки в ближайшие 3 ч, мороз ниже −15 °C или ветер выше 12 м/с | 1,0 | 0,2 |
| После заката | 1,0 | 0,3 (ночные категории — 1,0) |
| Будни 12:00–14:00 | еда — 1,0, остальное — 0,7 | 0,7 |
| Выходные до 12:00 без осадков | 0,6 (кофейни — 1,0) | парки — 1,0 |
| В остальных случаях | 0,7 | 0,7 |

**Разнообразие.** Карточки выбираются по одной, чтобы не выдать пять кофеен подряд. sim = 1 для той же категории, 0,5 для той же группы, иначе 0.

```latex
\text{next} = \arg\max_{i \notin S} \left[ 0.7\, s_i - 0.3 \max_{j \in S} \mathrm{sim}(i, j) \right]
```

**Карточка:** иллюстрация категории, название, время в пути на транспорте пользователя, контекстный чип («Дождь через час — крытое место»), состояние работы, рейтинг, строка «почему». Отдаёт ли Places API фотографии мест, не подтверждено, поэтому в прототипе — векторные иллюстрации категорий.

**Жесты**

- Вправо — «Хочу»: место сохраняется, появляется кнопка маршрута, α + 1.
- Влево — «Не то»: β + 1.
- Вверх или нажатие — карточка места.
- Под колодой три кнопки с теми же действиями: только жесты недоступны части пользователей.
- Поворот карточки — 15° × смещение / ширина; срабатывание при 35% ширины; тактильный отклик на пороге.

## 10. Автоматическое определение прогулки и уведомления

Прогулка определяется автоматически, без кнопок и режимов. Единственное ручное действие — выдать разрешения при первом запуске: без них Android не даёт приложению работать в фоне.

**Разрешения (онбординг, один раз)**

- `ACTIVITY_RECOGNITION` — распознавание активности.
- `ACCESS_FINE_LOCATION`, затем отдельно `ACCESS_BACKGROUND_LOCATION` («Разрешить всегда»; на Android 11 и новее выбирается на экране системных настроек).
- `POST_NOTIFICATIONS` (Android 13 и новее).
- В манифесте: `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_LOCATION`, `RECEIVE_BOOT_COMPLETED`.

**Почему нужны оба разрешения на геолокацию.** С Android 12 сервис переднего плана нельзя запустить из фона, кроме исключений; одно из них — событие перехода активности ([Android](https://developer.android.com/about/versions/12/foreground-services)). Но сервис, созданный из фона, получает геолокацию только при разрешении `ACCESS_BACKGROUND_LOCATION` ([Android](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start?hl=de)).

**Детектор прогулки**

- Activity Recognition Transition API, подписка на переходы `WALKING`, `RUNNING`, `ON_BICYCLE`, `IN_VEHICLE`, `STILL` ([Google](https://developers.google.cn/android/reference/com/google/android/gms/location/ActivityRecognitionClient?hl=sl)). Регистрация при старте приложения и после перезагрузки.
- В состоянии «идёт прогулка»: геолокация каждые 30–60 с с балансом точности и энергии, погода — раз в 10 минут, проверка триггеров — раз в минуту.
- Тип транспорта: `ON_BICYCLE` — велосипед; `WALKING` и `RUNNING` — пешком; `IN_VEHICLE` неоднозначен (авто или автобус), поэтому берётся транспорт из портрета.
- Android требует постоянное уведомление сервиса: тихий канал, текст «Идёт прогулка — подсказки включены».
- Состояния и переходы — на схеме в конце раздела.

**Погода**

- OpenWeather One Call 3.0: поминутный прогноз осадков на час и почасовой на 48 часов; собственная модель с обновлением каждые 10 минут; 1000 бесплатных вызовов в сутки ([OpenWeather](https://m.openweathermap.org/api/one-call-3)).
- Open-Meteo — перепроверка по часовому прогнозу. 15-минутные данные у него есть только для Северной Америки и Центральной Европы ([Open-Meteo](https://openmeteo.substack.com/p/sub-hourly-15-minutely-weather-forecasts)). Бесплатно — только некоммерческое использование, до 10 000 вызовов в сутки ([Open-Meteo](https://open-meteo.com/en/terms)).
- Условие «скоро дождь»: по OpenWeather ≥ 0,3 мм осадков за 15 минут с началом через 15–45 минут. Плюс подтверждение: вероятность осадков в этом часе по Open-Meteo ≥ 50% или ≥ 0,5 мм по почасовому прогнозу OpenWeather.
- Точность краткосрочного прогноза для Астаны не проверена (уверенность около 60%), поэтому текст уведомления говорит «по прогнозу».

**Триггеры уведомлений**

| Триггер | Условие | Что предлагаем | Не чаще |
| --- | --- | --- | --- |
| Скоро осадки | Условие выше, идёт прогулка | Крытые места, достижимые до начала; если их нет — режим плана | 90 мин |
| Холод или ветер | Ощущаемая температура падает на 6 °C за 2 ч или ниже −15 °C; ветер ≥ 12 м/с | Тёплые помещения рядом | 120 мин |
| Долгая прогулка | Прогулка ≥ 90 мин | Место для отдыха по портрету | 1 раз за прогулку |
| Время еды | 12:00–14:00 или 18:00–20:00, прогулка ≥ 30 мин без остановки на еду | Еда по портрету | 1 раз за окно |
| Скоро закат | До заката 20–40 мин, рядом парк или смотровая | Смотровая площадка или освещённое место | 1 раз в день |
| Низкий заряд | Батарея ≤ 20% во время прогулки | Кафе с Wi-Fi; розетки не подтверждены | 1 раз за прогулку |
| Цель закроется | Идёт навигация, прибытие позже, чем за 10 мин до закрытия | Альтернатива той же категории | 1 раз за маршрут |

- Общие ограничения: не больше 3 уведомлений в день; тихие часы 22:00–08:00; каждый триггер отключается в профиле.
- Кандидаты: `POST /v1/notify/candidates` — тот же конвейер, что в разделе 5, но фильтры задаёт триггер, Jev не вызывается.
- Текст: шаблон и одна фраза Claude Haiku 5.5 до 90 символов.
- Кнопки уведомления: «Маршрут» (сразу навигация), «Ещё варианты» (поиск с готовым запросом), «Не сейчас» (пауза триггера удваивается).

Прогулка подтверждается после 3 минут движения и 150 м смещения; ложный старт отменяется через 5 минут без смещения. При выходе из прогулки её итог (длительность, расстояние, район) уходит в портрет.

## 11. Экраны и интерфейс

Три вкладки: «Карта», «Для вас», «Профиль». Главный сценарий укладывается в один экран: карта и строка ввода снизу.

| Экран | Состав | Действия |
| --- | --- | --- |
| Онбординг | 3 шага: что умеет приложение; разрешения с объяснением каждого; транспорт по умолчанию | Выдать разрешения, выбрать транспорт |
| Карта | Карта на весь экран; плавающая строка ввода внизу; 3–4 чипа-подсказки над ней («Кофе рядом», «Прогулка на час», «С ребёнком»); кнопка «Моё местоположение» | Ввести запрос, выбрать подсказку |
| Результаты | Чипы «Jev учёл: …» над шторкой; шторка с 1–3 карточками; маркеры 1–3 | Убрать фильтр (поиск без повторного вызова Jev), «Маршрут», «Подробнее» |
| План | Вертикальная шкала этапов: точка, цель этапа, время; линия маршрута на карте | «Начать», «Открыть в 2ГИС» |
| Навигация | Карточка манёвра сверху; время прибытия и остаток пути внизу | «Завершить», «Звук», «Открыть в 2ГИС» |
| Карточка места | Состав — в разделе 7 | «Маршрут», «Позвонить», «Открыть в 2ГИС» |
| Для вас | Колода карточек и 3 кнопки под ней | Свайпы или кнопки |
| Профиль | Транспорт по умолчанию; переключатели триггеров; «Мой портрет»; статус разрешений; удаление данных | Правка, отключение, удаление |

**Карточка рекомендации:** название и категория; время в пути со значком транспорта; состояние работы («открыто до 22:00», «закрыто», «нет данных»); рейтинг и число отзывов; одна фраза «почему»; время на посещение; действие; метка источника («Данные 2ГИС» или «Идея модели»).

**Оформление**

- Jetpack Compose, Material 3, собственная палитра, светлая и тёмная темы; стиль карты в тех же тонах.
- Чипы фильтров появляются по событию `filters`, пока идёт поиск: пользователь видит работу Jev до готового ответа.
- Заглушки-скелетоны карточек вместо спиннера; пружинная анимация шторки и колоды.
- Доступность: зона нажатия не меньше 48 dp, контраст текста не ниже 4,5:1, подписи TalkBack для маркеров и кнопок.
- Язык интерфейса — русский; ответы Claude — на языке запроса.

## 12. Серверное API

Сервер — Python 3.12 и FastAPI в Cloud Run; приложение обращается только к нему, кроме тайлов MapGL. Ключи Jev, Claude, 2ГИС и погодных сервисов живут в Secret Manager.

| Метод | Путь | Назначение | Внешние вызовы |
| --- | --- | --- | --- |
| POST | `/v1/search` | ИИ-поиск, ответ потоком SSE | Jev, Places, Distance Matrix, Claude |
| GET | `/v1/suggest` | Подсказки при вводе | Suggest API |
| GET | `/v1/places/{id}` | Карточка места | Places API, кэш 24 ч |
| POST | `/v1/route` | Маршрут с манёврами | Routing API или Public Transport API |
| POST | `/v1/deck` | Кандидаты и тексты для «Для вас» | Places, Distance Matrix, Claude |
| POST | `/v1/profile/update` | Операции над портретом | Claude |
| GET | `/v1/weather` | Осадки на час и прогноз на 3 ч | OpenWeather, Open-Meteo, кэш 10 мин |
| POST | `/v1/notify/candidates` | Места для уведомления | Places, Distance Matrix, Claude |

**События SSE для `/v1/search`**

| Событие | Данные |
| --- | --- |
| `filters` | `JevFilters` и подписи чипов |
| `candidates` | До 8 мест: id, название, точка, категория |
| `answer` | Рекомендации (раздел 5) или план (раздел 6) |
| `error` | Код и текст для пользователя |
| `done` | Id запроса и задержки этапов |

**Запрос `/v1/search`**

```json
{
  "query": "тихое место с кофе и розеткой",
  "lat": 51.128,
  "lon": 71.430,
  "local_time": "2026-10-22T15:10:00+05:00",
  "transport_hint": "walking",
  "walk_active": true,
  "profile_summary": "кофейни +; тихо; пешком",
  "lang": "ru"
}
```

**Событие `answer`**

```json
{
  "mode": "simple",
  "items": [{
    "poi_id": "<id 2ГИС>",
    "name": "<название>",
    "category": "coffee",
    "eta_min": 6,
    "transport": "walking",
    "open_state": "open",
    "open_until": "22:00",
    "rating": 4.7,
    "reviews": 312,
    "why": "<текст модели>",
    "visit_min": 40,

```

**Защита и форматы**

- Заголовок `X-Install-Id` — случайный UUID на установку без персональных данных; лимит 60 поисков в сутки на установку.
- Единый формат ошибки: `{"code": "...", "message": "..."}`.
- Библиотеки: `httpx` (асинхронные вызовы), официальный SDK `anthropic`, `pydantic` для схем.
- Cloud Run: на время демо `min-instances = 1`, чтобы не было холодного старта.

## 13. Данные, приватность, безопасность

Точные координаты и история перемещений остаются на устройстве. Сервер получает только округлённую точку и ничего не хранит, кроме кэша ответов внешних API.

| Данные | Где хранятся | Кто получает | Срок |
| --- | --- | --- | --- |
| Точная геолокация | Только устройство (навигация, детектор прогулки) | Никто | Пока идёт сессия |
| Округлённая точка (3 знака, около 110 м) | Не хранится | Сервер, 2ГИС, погодные сервисы | Время запроса |
| История посещений и частые районы (geohash 6) | Устройство | Никто | 90 дней |
| Портрет | Устройство | Сервер и Claude — только сводка, на время запроса | До удаления пользователем |
| Текст запроса | Не хранится; в отладочной сборке — логи для тестов | Jev, Claude | Время запроса |
| Ответы 2ГИС | Кэш сервера | — | До 24 ч |
| Погода | Кэш сервера по ячейке geohash 5 | — | 10 мин |

**Правила**

- Jev не получает координат; Claude получает время в пути и названия мест, но не координаты пользователя.
- Логи релизной сборки: id запроса, задержки, коды ошибок. Без координат и текста запросов.
- Ключи внешних сервисов — только на сервере. Исключение — ключ MapGL в приложении, ограниченный по приложению в Менеджере Платформы.
- Удаление: одна кнопка в профиле стирает портрет, историю и кэш на устройстве.
- Честность ответов: «нет данных» вместо «открыто»; метки «Данные 2ГИС» и «Идея модели»; «не подтверждено» для атрибутов без данных.

**Хранение данных 2ГИС.** Официальных условий хранения найти не удалось. По стороннему обзору, коммерческое использование и автоматический сбор без отдельного соглашения запрещены ([toolfox](https://toolfox.ru/services/s/2gis)). Поэтому постоянная копия справочника не создаётся, а кэш живёт не больше 24 часов только ради экономии лимитов.

**Требование хакатона об автоматизированном сборе данных** закрывается автоматическим конвейером извлечения из API в момент запроса и снимками ответов для тестовых сценариев. Допустимость снимков уточнить у 2ГИС.

## 14. Нефункциональные требования, лимиты, бюджет

Узкое место прототипа — демо-ключ 2ГИС: 1000 запросов на сервис хватает примерно на 300 ИИ-поисков. Нейросети на таком объёме стоят около $3–4 в месяц.

**Оценка расходов на нейросети** (мой расчёт по ценам выше)

- Простой поиск: Haiku — около 6 тыс. входных и 0,5 тыс. выходных токенов, около $0,001; обновление портрета — около $0,0005; Jev — меньше $0,0001.
- План: около 4 ходов Sonnet по 8 тыс. входных и 0,6 тыс. выходных токенов, около $0,09.
- 300 поисков, 30 планов и 90 обновлений колоды — около $3–4 в месяц.

**Контроль лимитов 2ГИС:** счётчик запросов по сервисам на сервере; при 80% — предупреждение в лог; дальше — покупка ключа с нужными лимитами в Менеджере Платформы.

## 16. Этапы работ

Работа идёт в 9 этапов в указанном порядке; каждый заканчивается проверяемым результатом. При нехватке времени сокращается глубина, а не этапы: уведомления — до триггера осадков, колода — до текстов из шаблонов.

0. **Доступы.** Демо-ключ 2ГИС в Менеджере Платформы; ключ TypeSafe в `console.typesafe.ai` или доступ через шлюз; организация Claude Console, привязанная к подписке Max; подписка OpenWeather One Call 3.0 (активация ключа может занять до часа, [PyPI](https://pypi.org/project/iflow-mcp-rossshannon-weekly-weather-mcp/)); проект GCP с Cloud Run и Secret Manager. Результат: каждый ключ проверен запросом curl.
1. **Сервер, простой режим.** `JevClient`, клиент 2ГИС, конвейер раздела 5, вызов Haiku, поток SSE. Результат: curl по сценариям 1, 2, 5, 8, 10 возвращает корректный `answer`.
2. **Android, главный экран.** Карта MapGL в WebView, мост Kotlin ↔ JS, строка ввода, чипы, шторка с карточками, карточка места, онбординг. Результат: сценарии 1–5 и 7–10 с экрана телефона.
3. **Маршруты и навигатор.** Routing API, переключатель транспорта, пошаговая навигация, ссылка в 2ГИС. Результат: сценарий 14.
4. **Режим плана.** Оптимизатор, инструменты Sonnet, экран плана. Результат: сценарий 6.
5. **Портрет и «Для вас».** События поиска, `/v1/profile/update`, слияние, экран «Мой портрет», фоновая колода, свайпы. Результат: сценарий 13.
6. **Прогулка и уведомления.** Детектор активности, сервис геолокации, погода, триггеры. Результат: сценарии 11–12.
7. **Калибровка и замеры.** Пороги Jev на 60 запросах, прогон инвариантов, замер задержек и батареи по разделу 14.
8. **Материалы хакатона.** Репозиторий, документ сценариев и ограничений, презентация на 5–7 минут, демо-видео на YouTube по ссылке.

## 17. Риски и открытые вопросы

Главные риски — лимиты демо-ключа 2ГИС и неизвестная точность Jev и прогноза осадков на данных Астаны. У каждого риска есть проверка в первый день и запасной путь.

| Риск | Последствие | Что делаем | Уверенность в оценке |
| --- | --- | --- | --- |
| Исчерпан лимит демо-ключа 2ГИС | Поиск останавливается | Кэш, счётчики, покупка ключа в Менеджере Платформы | Высокая |
| Загрузки MapGL расходуют лимит демо-ключа | Карта съедает бюджет | Проверить статистику в первый день | Низкая, не проверено |
| Прямой доступ к Jev ограничен ранним доступом | Нет фильтров | Шлюзы Vercel, OpenRouter, Cloudflare, Opper через `JEV_BASE_URL` | Средняя |
| Jev хуже понимает русский и казахский или плохо откалиброван | Неверные фильтры | Набор из 60 запросов, пороги, запасной поиск по тексту | Средняя |
| В 2ГИС нет нужных атрибутов (розетки, тишина) | Фильтр не подтверждается | Мягкий бонус и пометка «не подтверждено» | Высокая |
| Прогноз осадков для Астаны неточен | Ложные или пропущенные уведомления | Двойное подтверждение, формулировка «по прогнозу» | Средняя, около 60% |
| Детектор ошибается или энергосбережение производителя выгружает сервис | Прогулка не определяется | Подтверждение 3 мин и 150 м; в онбординге — просьба отключить оптимизацию батареи | Средняя |
| Формат манёвров Routing API неудобен для голосовых подсказок | Навигатор беднее | Подсказки по геометрии маршрута; ссылка в 2ГИС | Средняя |
| Условия хранения данных 2ГИС неизвестны | Претензии к кэшу или снимкам | Кэш ≤ 24 ч, без копии справочника; уточнить у 2ГИС | Низкая |
